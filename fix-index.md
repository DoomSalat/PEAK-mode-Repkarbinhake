# fix-index — подозрительные места

| # | Где | Подозрение | Статус |
|---|---|---|---|
| 1 | `LinkRegistry.Links` | Возвращал один переиспользуемый список-снимок, который менялся под руками у вызывающего. | **исправлено**: `Links` — живая read-only коллекция словаря; `UntieActor` / `Clear` удаляют через внутренний буфер. Тест `UntieActor_WithSeveralLinks_DoesNotBreakIteration`. |
| 2 | room properties | Ключи развязанных связок копились в свойствах комнаты. | **исправлено в Core**: `UntiedKeySweeper` (все клиенты наблюдают записи, хост собирает развязанные старше N сек) + `ILinkTransport.DeleteIfUnchanged` (удаление через compare-and-swap, чтобы не стереть повторную завязку). Реализацию в Photon-транспорте сделать на этапе 3 — payload кодировать строкой, чтобы CAS сравнивал надёжно. |
| 3 | `CharacterDirectory.TryFind` | Линейный поиск на каждый вызов. | **исправлено**: словарь actor→Character, `Refresh()` раз в кадр (будет звать Back). |
| 4 | `VerletRope.Step` | Коллизия применяется при интеграции, до решения ограничений. Ограничения могут снова затолкнуть точку в камень, верёвка изредка «проваливается» в геометрию. Вариант: второй проход коллизии после ограничений (дороже в 2 раза по SphereCast). | **исправлено**: проверено в песочнице через Unity MCP — верёвка резала угол скалы, сила тянула висящего в стену. Теперь столкновения проверяются и после распрямления (каждые 3 итерации, по ходу смещения точки). Тест `TautRopeOverLedgeCorner_WrapsInsteadOfCuttingThrough`. |
| 8 | `PhysicsRopeCollider` | `SphereCast` не видит коллайдер, внутри которого начинается: точка верёвки, чуть вошедшая в пол, проваливалась насквозь навсегда (провисшая верёвка уходила на −5 м под землю). | **исправлено**: после проверки по ходу движения точка выталкивается из всего, во что попала (`OverlapSphere` + `ComputePenetration` с пробным триггер-коллайдером вдали от сцены — с выключенным коллайдером `ComputePenetration` не работает). Проверено в песочнице: провисшая верёвка лежит на земле. В моде нужен такой же пробный коллайдер. |
| 9 | `RepkaBack` (мод) | ~430 строк: ввод G/F8, наведение, правила рук, смотка с публикацией, силы, смерть, звуки, отладка. Сетевую часть и верёвки уже вынес (`RoomLinkSync`, `RopePresenterPool`), но Back всё ещё на грани «читается за один проход». Предложение: вынести ввод связки и смотку в отдельные инструменты. | **исправлено**: вынесены `LinkHoldInput`, `TestAnchorInput`, `RopeHands`, `ReelDriver`, `RopeForces`, `RopeDebugReport`, `LinkSoundFeedback`; `RepkaBack` 447 → 220 строк, только сборка инструментов и порядок кадра. |
| 10 | `SandboxRopeBack` (песочница) | ~600 строк, много отладочных сценариев (скала, автоподъём, смерть, выход). Для песочницы терпимо. | **исправлено**: вынесены `SandboxCrew`, `SandboxRopeVisuals`, `SandboxRopeForces`, `SandboxLifeRules`, `SandboxCliffScenario`, `SandboxOverlayReport`, `SandboxClimberTint`; `SandboxRopeBack` 699 → 367 строк. Регрессия в Unity: автоподъём, смерть, выход — как до рефакторинга. |
| 5 | `SandboxSceneBuilder` | Геометрия уровня (позиции/размеры блоков и камней) — инлайн-числа, не константы. | **отклонено**: это данные раскладки уровня, а не логика; оставляем как есть. |
| 7 | room properties, ключи концов | `UntiedKeySweeper` убирает только ключи связок. Ключи концов `rkb.end.A_B.<actor>` остаются после развязки (максимум 2 на пару игроков, хвосты старых завязок игнорируются по `TieId`). Растёт ограниченно, но новые игроки получают их в снапшоте комнаты. Вариант: хост удаляет ключи концов вместе с ключом связки. | **принято в работу**: этап 3, вместе с Photon-транспортом (см. PLAN.md). |
| 6 | Sandbox, слои | Капсулы-игроки на встроенном слое `Ignore Raycast`, а не на своём. | **отклонено**: только песочница, в мод не попадает; оставляем как есть. |
| 11 | `RopeHoldPoses` (мод) | Вращение катушки у чужих игроков считается по изменению их `Reel`, а `Reel` приходит по сети ~10 раз в секунду — колесо будет поворачиваться ступеньками. Вариант: сглаживать угол между приходами. | **новое**, ждёт решения |
| 12 | `TestDummy.IsGrounded` | Каждый вызов делает `Physics.Raycast`, а `FootingOf` манекена спрашивают несколько раз за кадр (устойчивость, отладка). Только отладочный манекен, но лишняя работа. Вариант: кэшировать раз в FixedUpdate. | **исправлено**: `TestDummy.Refresh()` раз за кадр, `IsGrounded` — кэш |
| 13 | `TestDummy` | Манекен не переживает смену сцены: объект уничтожается, `IsPlaced` становится false. Связка с ним остаётся в реестре до выхода из комнаты, просто невидимая. Вариант: при `IsPresent == false` развязывать локальные связки сразу, а не только через хостовое правило вышедших. | **исправлено**: `TestDummyInput.Tick` развязывает связку с пропавшим манекеном сразу |
| 14 | Core: `HandOverHand`, `CoilShape` (+ тесты) | После перехода на ванильную катушку больше нигде не используются (перехват рук и витки у бедра убраны). Мёртвый код в Core. Вариант: удалить вместе с тестами. Core — правка только с согласия. | **исправлено**: удалены вместе с тестами (рефакторинг по запросу) |
| 15 | `SpoolProps.CopyVisual` | `TryGetComponent` вызывается не в Awake, а при первом взятии верёвки (копирование префаба катушки). Один раз на держащего, но формально нарушает Rule 3. Вариант: строить шаблон копии один раз при старте и потом клонировать его через `Instantiate`. | **исправлено**: шаблон копии собирается один раз, держащим — `Instantiate`; ссылки хранит компонент `SpoolProp` |
| 16 | `HudPatches` | Виджеты (прицел, подсказка) и исходная позиция кольца лежат в статических полях патча и создаются в `GUIManager.Start` — при пересоздании HUD (смена сцены) старые ссылки заменяются новыми, но если `GUIManager` уничтожен, а новый ещё не создан, патч не трогает их только благодаря проверке на null в Unity. Вариант: отдельный HUD-инструмент вместо статики. | **новое**, ждёт решения |
| 17 | `RopeWrapProbe` + лог `SpoolProps` «copied mesh» | Временная диагностика (огибание скалы, лишние руки у катушки). Пишет в лог в обычной игре. | **исправлено**: удалены |
| 18 | `VerletRope` (Core), огибание в игре | Рельеф в игре — меш-коллайдеры-оболочки. Если ограничения протащат точку за поверхность за один шаг, изнутри оболочки её ни `SphereCast`, ни `ComputePenetration` не видят — точка остаётся за скалой. В песочнице были сплошные коробки, поэтому не проявлялось. Вариант: проход по цепочке — свип каждой точки от соседней (`Resolve(points[i-1], points[i])`), начиная от закреплённого конца. Правка Core. | **неактуально**: `VerletRope` удалена, огибание теперь делает `RopeWrapPath` (контакты на рёбрах) |
| 19 | Core: `VerletRope` (+ тесты, `IRopeCollider`-проход по цепочке №18) | После перехода на `RopeWrapPath` + `RopeSag` больше не используется ни модом, ни песочницей. Вариант: удалить вместе с тестами (правка Core — с согласия). | **исправлено**: `VerletRope` и тесты удалены, `IRopeCollider` слит в `IRopeObstacles`, `PhysicsRopeCollider` → `PhysicsRopeObstacles` |
| 20 | `RopeWrapPath` | Контакт ставится только при движении (поиск ребра между прошлым и текущим положением). Если верёвка «телепортировалась» сквозь стену (телепорт игрока, лаг сети), огибания не будет, пока концы не подвинутся — верёвка просто пройдёт сквозь. Вариант: при большом скачке конца сбрасывать путь. | **исправлено**: скачок конца больше `MaxEndJump` (3 м) начинает путь заново, тест `EndTeleportedFar_StartsAFreshPath` |
| 21 | `RopeSag` | Длина провиса считается приближением параболы (≈ ±10%), при очень большом запасе верёвка визуально короче настоящей. На физику не влияет. | **новое**, ждёт решения |
| 22 | `GetComponent*` вне `Awake` в моде (`VanillaRopeSpool`, `SpoolProps.GripCenter/CopyVisual`, `HudPatches` — клон подсказки, `PlayerListPatches` — кнопка кика, `TestDummy` — примитив) | Мод работает с чужими префабами игры, ссылок через `[SerializeField]` у него нет. Все вызовы — один раз при создании объекта, не в цикле кадра. На своих новых объектах `GetComponent` заменён результатом `AddComponent`. | **новое**, ждёт решения: принять как исключение из Rule 3 для мода или искать другой путь |
